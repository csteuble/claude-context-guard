# context-guard

Chris's context guard, a Claude Code mod. Built 2026-10-19, rebuilt 2026-11-04 on his rulings of that day.

What it does:

1. **Meter.** The engine pushes the context fill on every change (`session.measure`). No timer, no tokens.
2. **Three warnings** at fixed points of 60, 65, and 70 percent, each a question box (the one channel both the desktop app and the phone draw; toasts, the status line, bands, panes, log rows, and native notifications were all tested 2026-11-04 and do not show). Each fires once per session and re-arms after a compaction. NN is the actual percent at that moment. Buttons: `Good Day to you` / `I said Good Day!`. The answer is not used; either button closes the box.
   - `CONTEXT: NN% - Wrap up soon.`
   - `CONTEXT: NN% - I said wrap up!`
   - `CONTEXT: NN% - WRAP THE FUCK UP!!`
   The real auto-compaction fire point is still measured on every auto-compaction and stored per window size; it no longer moves the warnings.
3. **On an auto-compaction:** a box with the buttons `Sure fucked that up` / `Fuck fuck fuck fuck`. While P40 is on (Chris "1", 2026-11-22) it reads "Auto-compacted at NN percent before P40 could. Stay in this session. Nothing to do.", and the summary also carries the order to re-read Global Memory before the first reply; after `P40 off` it is the old scolding box ("We blew it ... say handoff and start a new session immediately"). A subagent's own compaction gets none of this. Also, the fire point recorded, and the standing rules pinned into the compaction summary with a NEXT section.
4. **`mcp__context-guard__context_fill`**, a tool the model calls only when Chris asks where context is at. Zero cost until asked. It answers with the readout, which the model shows exactly as returned: two blank lines, `**CONTEXT: NN%** (tokens of window tokens)`, two blank lines. Each blank line is a paragraph holding a non-breaking space, so the chat cannot squeeze it away. When the rules did not load from GitHub, one blank line and the italic lines `*RULES BROKEN*` / `*Start a new session or tell Claude to fix it.*` (joined by a hard line break) go before the closing blank lines. Since 1.0.2 it is registered as a deferred tool: the model loads it with ToolSearch (`select:mcp__context-guard__context_fill`) and then calls it. Deferred is what gets it announced when the mod attaches after a conversation has started (the 2026-11-06 mid-session attach left a kept-in-front tool registered but never announced).
5. **Standing rules ride beside every message Chris types** (`prompt.submit` context, about 600 tokens). This replaces the 30-minute rules-reload timer. The text comes from `Standing Rules.md` in this repo, fetched at every session start; `hooks/rules.ts` holds a baked fallback for when the fetch fails. `prompt.compose` and `prompt.context` are blocked for mods by the default security plugin, so they are not used. When the fetch fails, a box pops at session start: `RULES BROKEN` / `Start a new session or tell Claude to fix it.`, buttons `Got it` / `Thanks`.
6. **Shortcuts**, read only when they are the whole message (any capitals; trailing periods, question marks, and spaces allowed):
   - `CC` or `Context`: the reply is the readout alone. A mod's only way to write in chat without a Claude turn is a plain notice, which cannot carry the bold line or the forced blank lines, so the mod writes the readout into the message's hidden context with the order to reply with it alone, and Claude replies.
   - `CC TEST`: the mod pops the 60 percent warning box once with the current percent and drops the message, so no Claude turn runs. The drop's reason is a zero-width space, so no text line shows. The test does not use up the real 60 percent warning.
   - `mute` or `unmute` (no question mark): the mod runs `tools/Set Mute.ps1 on` or `off`, which SETS the PC's default playback device muted or unmuted through the Windows Core Audio API (never a toggle), then hands Claude the one-word reply, `Muted.` or `Unmuted.`, the way `CC` hands over the readout. A failed set makes the reply one line saying so. If the engine refuses the mod's `$.process.run`, Claude is handed the exact PowerShell command to run instead. Works from the phone over Remote Control, since the hook runs on the PC.
7. **P40 compact in place: `mcp__context-guard__compact_now`** (1.0.16), a second deferred tool. A session that is getting full writes its notes file to disk (`_Claude\P40 Compact Notes\<session title>.md` in the project folder), calls the tool with the notes path, its IN PROGRESS line, and the one next action, and ends its turn. About a second after the turn ends the mod queues a real `/compact`, as if Chris had typed it (`$.command.run`; `$.session.compact` is refused in a session the desktop app hosts), so the session keeps its row and its conversation. A call that names no notes file on disk is refused. If a waiting message has started a new turn, the compaction waits for that turn to end; a stopped turn drops it. The instructions demand a `P40 RESUME` block in the summary whose FIRST line tells the session to read all of Global Memory and then the notes file before its first reply. Each step is written to `P40 Compact Log.txt` beside the notes file. Nothing calls the tool by itself: the warnings are unchanged.
8. **P40 auto compact** (1.0.17, Chris's rulings of 2026-11-21): the three warning lines are the trigger. At 60 percent a question box asks `Context 61%. Auto compact will begin in 1 minute.` with the buttons `Compact now` and `Wait`. Compact now, or a minute with no answer, starts it; Wait holds it until the next line. At 65 percent (only after a Wait) the same box again. At 70 percent it starts with no box. Starting it means the mod submits a prompt of its own (from a one-second timer; the engine refuses a prompt from inside a hook that holds the turn), which makes the session open with `Context 71%. Auto compact is starting now.`, write its notes, and call `compact_now` (item 7). A jump past several lines acts once, on the highest. A session start or a mod reload fires nothing: lines already passed are only marked as passed, so an idle old session never asks. The mod cannot take its own box down; since 1.0.24 the companion plugin `context-guard-box` (item 13) closes it when the minute is up. Without the companion the box stays until tapped, and an unanswered box delays the queued `/compact` by about a minute. **Easy to put back:** the whole message `P40 off` in any session stores a flag that brings back the old three warning boxes (item 2) in every session, with no release; `P40 on` returns the auto compact. A deferred test tool, `mcp__context-guard__p40_test` (line 1, 2, or 3), runs one line's step at the current fill when the turn ends.

9. **One message per turn** (1.0.21, Chris 2026-11-21, the guard behind his rule "One message per turn, and it comes last"): in a main-loop turn, text the model writes before a tool call is held back (never shown, never recorded) and handed back to the model beside that tool's result, with the order to put what he needs in the turn's one message at the end. What goes out before the tools: the first `Working on X, about N min` line of the turn (later ones are dropped), the auto compact's start line, and the reply to a message he typed while the turn ran. To know whether a tool call follows, a step's text is kept until the step shows a tool call or its stop, so the last message appears whole, not word by word. When anything came before the reply in a turn, a line of sixteen heavy dashes is stamped above it (his pick: "some sort of visual break ... it all blends"). Held text in a turn that ends with no last message is shown beneath its end. The whole message `One message off` stores a flag that switches the guard off in every session, with no release; `One message on` returns it. Hooks: `turn.start`, `turn.step` (a streaming hook), `tool.call` (every tool, for the note), `turn.complete`.

10. **No context line while P40 is on** (1.0.23, Chris 2026-11-22): a session that compacts by itself no longer needs its fill shown on every reply, so the context line order (the `Context NN% ▓▓▓░░░░░░░` line that opened every reply since 1.0.13) rides beside his message only while the P40 switch is off. **Tied to the same switch, so it comes back with one message:** `P40 off` brings back the context line and the old warning boxes in every session, with no release; `P40 on` takes both away again. `CC` still gives the number any time. The first standing rule now reads "The TLDR line first ... If the mod hands you a context line that turn, that line goes above it", so it holds in both states.

11. **The reply header** (Chris 2026-11-22: he reads on his phone, queues several messages, and could not tell which reply answers which; his words: "horizontal line, no spacing, no blank lines at all, and then the text that it's addressing, and then a blank line, and maybe that text is italicized, and then your response"): a reply to a message he typed opens with his words in italics in a markdown quote bar (`> *his words*`, one line), then one blank line and the reply. Above the quote sits the line of heavy dashes and a blank line: on his phone every kind of line break under the dashes left a full gap (his screenshot of 2026-11-22), so he picked the quote bar for his words, and then asked for the line back above it ("I know it adds an extra blank line, but it's easy for me to scroll quickly and identify, so make sure you put that back in"). So a reply to a message he typed opens: the line, a blank line, the quote, a blank line, the reply. His words are put on one line, characters markdown would act on are escaped so they show as typed, and they are cut to 100 characters (at a word boundary when one is in the last 20) with `…`; words that clean to nothing get the bare line rule. The turn's last message carries the words of the message that started the turn, always, even when nothing came before it; the reply let through for a message he typed while the turn ran carries that message's words. His typed message is one that reaches `prompt.submit` from the terminal, the phone (Remote Control), or the desktop app (origins `composer`, `bridge`, `sdk`) and is not a slash command, a meta prompt, a shortcut, or the mod's own auto compact prompt. A turn with none of his words (the mod's own prompt, a task notification) keeps the bare line, only when something came before the reply. Never doubled: a line or a quote the model wrote itself is taken out before the header is stamped, and a reply that already opens with the whole header is left alone. Shortcut replies, the working line, the auto compact start line, the guard off, and subagents get no header.
   Since 1.0.31 (his phone, 2026-11-22 19:38) a quote of his words the model typed at the top of its reply is taken out even when it differs a little from the mod's (a double space, a cut at another length, italics, escapes, a trailing `…`), here and under the full-message row; a quote line that is not a copy of his words stays.
12. **The full-message row** (Chris 2026-11-22: "can I have a ... where I could click it and it would expand out and show more"): when his typed message is longer than the 100 characters the quote shows, the mod hands Claude an order beside it (`FULL MESSAGE ROW`): once the tools are done, make one step that holds only the text `QUOTE` and one call of the `view_full_message` tool (deferred, no arguments), then write the message in the next step. The mod turns `QUOTE` into the quote of his words, and the tool's result is his whole message. On his phone that reads: the quote, then a row "Used View Full Message" that opens to his whole message on a tap, then the reply. Why this shape: his phone shows nothing a mod draws on a row, and a tool call shows as a row of its own only when text sits on both sides of it (calls in a run fold into "Used N tools"); a tap on such a row opens a pop-up he can read (his phone, 2026-11-22). The reply under the row is not stamped with the quote a second time. A message typed mid-turn gets its own quote and row on the reply it lets through. `QUOTE` with no row call is dropped and never held. Since 1.0.29 a row call with no `QUOTE` before it in its step (his phone folds such a call away) is sent back: the tool answers with an order to make the call again now, in a step holding only `QUOTE` and the call, and hands back any text held before it. Since the 2026-11-23 fix (in the next release), a step whose only text is a typed copy of the header for those words (the line of dashes and his quote, or the quote alone, cut at any length) counts as `QUOTE` and is swapped for the mod's own quote; before it, the model typed that header in place of `QUOTE` 13 times in two days, and each one was held and sent back. The order and the redo now also say that step is the one exception to writing nothing before a tool call. At most two such redos a turn; after that the quote stays on the reply as in item 11. The mod does not put the quote in front of the call itself: the engine keeps a step's blocks by their index, so a text block of the mod's own there would push the call and every later block along and the engine would drop its own record of the call. A second row for the same words never prints the quote twice and is not sent back. The tool refuses a subagent and says so when there are none of his words. Not yet seen on his phone in this exact shape (the tests were echo tools in a throwaway); costs one extra model step on each reply to a long message.
13. **The box closer, a companion plugin** (`context-guard-box`, on the `box` branch of this repo, 0.1.0 with mod 1.0.24; Chris 2026-11-22: "I stared at it for a couple of minutes and it never went away"): the auto compact box of item 8 ran its minute and started the compaction, but stayed on screen until tapped (7 minutes in Porter on 2026-11-22). A question box runs through every mod's hooks but the one that asked, so the context guard cannot close its own box and a second plugin does: a `tool.call` hook on `AskUserQuestion` that acts only on the box whose words are `Context NN%. Auto compact will begin in 1 minute.`, lets it come up, and answers the call itself with a deny when 60 seconds pass with no tap. A tap inside the minute goes through untouched. It is a second entry in this repo's `marketplace.json` (a `github` source with `"ref": "box"`: a plugin folder may not hold another plugin's `plugin.json`, and the context guard is the root of `main`, so the companion has its own branch) and is switched on beside the context guard. Its vault source copy is `Work\Vault & Memory\Context Guard Box Mod\`; a change there is committed to the `box` branch by hand. Since 0.2.0 (with mod 1.0.31) it also closes the 60-second Peck box (item 16). **It works only in a session that loaded it.** The desktop app hands a session its plugins when it starts the session's process. A later reload does not add a plugin installed since then. So on 2026-11-22 the companion never ran in Porter, whose process dated from 11-21, and the 65 percent box at 17:57 stayed on his phone for 17 minutes while the compaction ran. A session started, or stopped and started again, after the companion was added has it. Since 1.0.31 the mod writes a line in `P40 Compact Log.txt` when a box of its own is still up a moment after its minute, so this shows in the log.
14. **The long turn guard** (1.0.30, Chris 2026-11-22: "you do shit in the background and maybe I wanna make that a rule so that you can fucking answer me and we keep replying and dealing with shit"; the rule is core O21 in Global Memory). A message he sends while a turn runs does not reach the session until the turn ends, so any long turn means he is ignored, and a rule alone had not held. In a main session only: (a) a `Bash` or `PowerShell` call that is not `run_in_background` and plainly waits over a minute is refused before it runs, with the order to run it in the background, say one line, and end the turn: its `timeout` is over 60,000 ms, or it has no timeout (two minutes by default) and its sleeps add to over a minute (`sleep`, `Start-Sleep`, `timeout /t`, `Thread::Sleep`, `time.sleep`, times a loop's stated count) or it sleeps in a loop with no fixed end. A timeout of a minute or less is never refused, a sleep counts only where a command starts, and script text a command only writes (a heredoc, a here-string) is skipped, so ordinary quick work is not refused. (b) Once a turn has run over a minute of its own time, a note rides beside the next tool result, at most once a minute, telling the model to hand what is left to a background worker or a background command and end the turn; it never blocks a call. (c) Every turn that ran over a minute of its own time gets one line in `Long Turn Log.txt`, beside `P40 Compact Log.txt` in the project's `_Claude\P40 Compact Notes\` (kept only if that folder exists, as P40's): the time, the session's title (from the settings hooks' own `UserPromptSubmit` and `SessionStart` events, else the session id), the seconds, and the tool calls. Time a question box the model opened waits on him, and a compaction inside a turn, are not the turn's own; the mod's own boxes do not hold the clock. The mod's own auto compact turn, and a turn that called `compact_now`, get no note and no log line. Main or worker: a subagent (`agentId`) is skipped; a worker session another session started says so with a line holding only `LONG TURNS OK` in its brief, which the mod reads at `prompt.submit` and keeps by session id, so a mod reload mid-run still knows it. The engine gives a mod nothing more reliable: his main and a worker both get their first prompt from the desktop app's host, and a relay of his main starts exactly as a worker does; titles are not used. (d) **Switch:** the whole message `Long turn off` stores a flag that switches a, b, and c off in every session, with no release; `Long turn on` returns them (the reply is one line, as for `One message off`). It shares the one-message guard's hooks (the engine takes one hook per event with no matcher) and leaves that guard's work as it was: held text and the long turn note ride the same tool result.
15. **The Peck type** (1.0.31; Chris "1" at 11:50 on 2026-11-22, and his worker effort and model ruling at 12:59). A Peck is Chris's word for a helper a main starts (2026-11-22 evening: "I don't think they're workers. they're pecks", then "Pecks"). The mod adds a Peck type, `context-guard:peck`. A main starts a Peck as that type (the Agent tool, `subagent_type` `context-guard:peck`), and the Peck gets his defaults without naming them:
   - Model: Opus.
   - Effort: High.
   - Tools: every tool the main has.
   - It compacts its own conversation at 300,000 tokens and keeps going.
   A model or effort named on the start still wins, so a main still names them by the job (rule E1). The type has its own system prompt, written to match the general-purpose worker's. The name `peck` is his (it was the placeholder `worker` until 2026-11-22 evening). Not built: anything that makes a main use the type. Today only the type's line in the list of agent types says to use it in place of general-purpose.
16. **The 60-second ask for Fable or Max** (1.0.31; rule E6, Chris 2026-11-22 13:08). A deferred tool, `mcp__context-guard__ask_a_peck` (his name; his phone shows the call as "Used Ask a Peck"). How a main uses it:
   - When it thinks a Peck's job needs Fable or Max, it calls the tool as the last thing before the start.
   - It names the higher option, the lower option, and the job in a few words (for example "Fable at Max", "Opus at High", "recheck every formula in the wood usage report").
   - The box reads three lines, his words as approved on 2026-11-22 ("3 approved"):
     ```
     Job: recheck every formula in the wood usage report
     Run this Peck on Fable at Max?
     No answer in 60 seconds: Opus at High.
     ```
     Its two buttons are the two options.
   - The answer starts with `USE:` and names the option to start the Peck on.
   - A tap on the higher option: that option.
   - A tap on the lower option, no answer in a minute, or a box closed with no pick: the lower option.
   - Words typed instead of a tap go back to the main, with the lower option unless his words plainly pick the higher one.
   - When the answer is the lower option because the box got no tap (no answer in a minute, a box closed with no pick, words typed instead of a tap, or no box at all), it hands the main one line for the Peck's brief. The line makes the Peck's report say it ran lower than the main wanted, and why. A tap on the lower option is his own pick and gets no such line (Chris "1", 2026-11-22 evening).
   No box, and the lower option at once, in three cases: the call says `unattended: true` (an unattended run); the session is a Peck session (its brief carried the line `LONG TURNS OK`, item 14); the call comes from a subagent. The minute the box waits on him is not counted as the turn's own time (item 14). The companion (item 13) takes the box down at its minute. If the box is still up a moment after the minute, the answer tells the main to say in one line that it no longer counts, and the P40 log notes it. Whether the box shows the three lines as three lines on his desktop and his phone has not been seen yet.

## Changing the rules

Never edit `Standing Rules.md` or the baked copy by hand. Since 1.0.8 the one source is the STANDING RULES section of Chris's Global Memory (`C:\HomeInnovation\000 VAULT\_System\Global Memory.md`); the vault script `Check Rules Copies.py --push "<what changed>"` writes both files from it, bumps the version, pushes to `main`, and updates the PC install. Every new session picks up `Standing Rules.md` at start; the baked copy changing makes each rules edit a code change (run the tests and the delivery check).

## Install

At the prompt of a terminal Claude Code session:

```
/plugin install context-guard --marketplace csteuble/claude-context-guard
```

Answer `y` to add the marketplace, then pick a scope (user). The repo is private; the installing account needs access to it and GitHub set up for Claude.

## Checks

`claude plugin validate .` passes; `tsc -p .` is clean once the engine has laid the types; `claude plugin test .` runs 102 tests; the companion's 5 tests are on its own branch, `box` (warnings and their text, jump, auto and manual compaction, stored fire point, rules fetch and fallback, RULES BROKEN box and readout, the tool, the shortcuts, mute and unmute).
